# 流光快剪本地素材处理

`metadata_watermark_processor.py` 和 `quality_optimize_profile.py` 为现有本地处理器的源码入口，运行时优先读取本目录，并在受管运行目录保留同版副本。Python、NumPy、FFmpeg 与 FFprobe 沿用 `quick-cut/runtime/metadata-watermark` 的隔离环境。

## 元数据清理

- 保留既有图像处理、水印和固定 QP 编码合同；清理生成新文件，绝不覆盖源文件。
- 禁止自动继承全局与所有音视频轨道的来源元数据，清除章节、字幕和数据轨道，去掉 H.264 SEI。
- MP4 按真实 atom 边界擦除 `udta/meta/uuid` 可选元数据、处理器名称、压缩器名称、媒体创建/修改时间。保留 box 字节长度和媒体偏移，不扫描替换压缩媒体内容。
- Python 在发布最终文件前执行 FFprobe 属性残留校验；Node 再独立核验全部轨道，失败文件不会交付。日志只记录属性数量和字段名，不记录来源属性值。
- 允许保留解码所需的容器品牌/版本、视频尺寸、帧率、编码格式等技术信息以及未指定语言 `und`。Windows 文件系统的新建/修改时间不属于视频内嵌元数据，正常生成文件仍会有这些时间。

## 轻微音画优化

- 保留原有保守的亮度、色彩、降噪、锐化和音频处理参数。
- 通过 FFmpeg `-progress pipe:1` 提供真实编码进度；MP4/MOV/MKV/AVI 明确使用相应容器，WebM 使用 VP9/Opus。
- 终检通过后才覆盖操作者选中的原文件；发生文件占用、恢复失败或服务中断时，保留唯一原件备份，不吞掉恢复错误后继续删除备份。
- 清理模式与轻微优化模式是独立用途；轻微优化继续按既有行为保留来源描述性元数据，需要清理属性时使用“清理元数据”。
