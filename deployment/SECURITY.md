# 本地部署安全与账户隔离

本次审计对应 2026-11-26 的本地 Windows 部署。默认只允许 `127.0.0.1` / `localhost` 的当前服务端口；没有启用外网域名、反代或端口转发。

## 已落实的边界

- 两个普通账户的项目、画板、人物包、背景、快剪和商品生产线按持久归属读取；项目名相同也不能访问管理员的历史名称目录。共享方法库仍按原有明确权限共享。
- 普通账户提供的服务器视频路径仅能落在自己的当前画板目录，使用真实路径再次检查 junction/符号链接。管理员可选本机外部视频；UNC/设备/相对路径均拒绝。普通账户应通过浏览器上传素材。
- 服务器桌面、Windows 文件选择器和打开目录仅限管理员。普通账户的快剪“本地视频选择 / 输出目录 / 打开目录”入口会返回权限提示；这些操作涉及共享宿主 OS，当前尚无普通账户的完整浏览器替代流程，不能宣称其三模式均已具备远程多用户功能。管理员的本机三模式保留。
- 所有上传背景均要求登录与归属，旧人物图片只给管理员，内部生图读取辅助函数执行同样规则。匿名首页使用默认动效，其他账户不继承管理员保存的背景或内嵌图片。
- 私有 API 禁止缓存并包含 Cookie 变化标记。API 文件响应带禁止执行脚本的 sandbox CSP；人物图片也不允许长期浏览器缓存。受保护页面验证实际会话，伪造一个 Cookie 名称不能打开页面。
- 写请求验证 Origin / Fetch Metadata，并检查可信 Host；拒绝 DNS rebinding、跨站表单和不可信域名。大文件流式上传在自己的 Route Handler 中执行相同检查，避免 Proxy 复制整段视频。
- 内部带 Cookie 的请求固定发送到本机当前端口，不使用浏览器提供的 Host、转发 Host 或其他端口。
- 登录与注册按账户、来源和全局预算计数，计数持久化到 SQLite；默认忽略转发 IP。密码与身份字段有长度限制，一次性邀请码在事务内核销。禁用账户同时吊销旧会话，重新启用也不会恢复旧 Cookie。
- 远端任务轮询要求调用记录中的账户、通道、服务商和任务 ID 同时匹配；画板视觉 PATCH 不能写入执行状态、远端任务句柄或清理凭证。未登记的旧任务不会仅凭任务 ID 放行，也不得因此自动重新付费提交。
- 关闭生产浏览器 Source Map 和 X-Powered-By；拒绝配置、源码目录、Git、数据库、主密钥和 map 文件请求。只有 `public/` 的公开资源和必要前端编译产物应该能被下载。
- 本机数据根与主密钥原有 ACL 已仅限当前 Windows 账户、SYSTEM 和 Administrators；源码根原来对 Authenticated Users/Users 开放，现已收紧到同一范围，正式 PS1 启动脚本也已收紧。原根权限 SDDL 保存在 `D:\3100\system\maintenance\security-20261126\source-acl-before.json`。已核对源码文件、启动脚本和 Git 配置继承正确。新安装脚本同步保护源码与数据根，重复安装保留已配置的 HTTPS/可信 Origin 设置。

## 以后启用反向代理

1. 复用 [Caddyfile.example](Caddyfile.example)，使用真实域名与 HTTPS，只将请求转发到 `127.0.0.1:3100`。此文件是参考配置，本轮没有安装或部署 Caddy。
2. 在 `.local/config.json` 设置 `publicOrigins` 为精确的 HTTPS Origin；多个值用逗号隔开。设置 `secureCookies: true`。设置 `trustProxy: true` 的前提是仅本机代理能访问服务，并且代理覆盖 `X-Real-IP`，不能继承外部客户端给的值。
3. 原电脑统一 PS1 启动器对应读取 `LUMA_PUBLIC_ORIGINS` 与 `LUMA_TRUST_PROXY`；检测到 HTTPS Origin 时启用 Secure Cookie。不要对公网开放 3100，不要把项目、数据或 `.runtime` 配成静态站点根目录。
4. 不缓存 `/api/*` 或已登录页面。保留 Cookie、Range、SSE/流式响应和大文件上传；反代自身另外配置连接/流量与上传配额。
5. 本轮只验证本地部署与配置规则，没有验证任何真实公网 TLS、CDN、网关、反代安装或防火墙规则。

## 源码与破解的实际边界

- 浏览器必然取得前端 JavaScript / CSS，可被查看和分析；压缩、隐藏 Source Map 或混淆不能成为保密或授权机制。权限、凭证、文件归属始终在服务端执行。
- 完整源码和运行环境交付给另一台电脑的控制者后，对方拥有本机管理员权限便能读取或修改代码、数据库与解密主密钥，绕过本地授权。完整可迁移源码交付和“安装者绝对拿不到源码、无法破解”不能同时保证。
- 2026-11-26 所有者明确授权暂时公开 GitHub 仓库，以便新电脑未登录访问；该决定替代此前私有要求，源码与 Release 现可公开下载，未设置自动恢复私有。不要将密码、Key、数据、SQLite、`.local`、`.runtime` 或本机密钥提交进源码仓库。
- 若将来要把核心逻辑对使用者保密，需要由受控服务器保留核心逻辑并提供 API，这会改变当前完整本地部署的产品目标，应另行决定。
- 当前修复不是对未知漏洞或物理设备失陷的零风险保证。依赖漏洞库、第三方模型包供应链、外置 Node/Python/代理程序及其他磁盘父目录权限、GitHub 当前协作者与 Token 权限、外部反代安全需另行针对真实环境核验；本轮只收紧应用目录与启动文件 ACL，没有更改 Windows 账户或其他应用权限。
